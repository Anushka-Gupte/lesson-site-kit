# Agent: QA + README. Phase 3, runs after the three lessons are merged.
Worktree `../wt-qa`, branch `agent/qa`, port 3105. Handoff: `docs/HANDOFF-qa.md`.
Read `SPEC.md`, `AGENTS.md`.

## Mission
Be the sceptical reviewer. Find what is broken, measure it, and report it. You may only fix things inside your own lane; everything else goes in the report for the human.

## You own
`tests/**`, `scripts/qa_*`, `.github/**`, `README.md`, `docs/QA-REPORT.md`, `docs/HANDOFF-qa.md`.

## Deliverables
1. `scripts/qa_links.py`: crawl all pages, report broken links, missing images and missing alt text. Exit non-zero on failure.
2. `scripts/qa_numbers.py`: for each lesson page, extract the numbers that appear in the matching `content/*.md` "measured" and "spec" tables and check they appear unchanged on the page. Report mismatches.
3. Run axe-core (or an equivalent accessibility checker available without adding runtime dependencies) and Lighthouse mobile on all five pages. Put real scores in `docs/QA-REPORT.md`, with the command you ran. If a tool could not be run, say so; never write estimated scores.
4. Check at 360px, 768px and 1280px, light and dark: no horizontal scroll, no overlapping text, no console errors. Screenshots into `tests/screens/`.
5. `.github/workflows/pages.yml` that deploys the repo root to GitHub Pages.
6. `README.md`: what this is, how to preview locally, how it was built (agent lanes and phases), and credits.
7. `docs/QA-REPORT.md`: a table of issues (page, problem, severity, owner lane, suggested fix) and the final scores.

Tooling rule: any Node tool (Lighthouse, axe) lives only inside `tests/` (`tests/package.json`); never add a root `package.json`.

## Acceptance
Every claim in the report is backed by a command output you actually ran. Finish with `docs/HANDOFF-qa.md`, then stop.
